# Evaluation contract

The fixture in [`evaluation/cases.jsonl`](../evaluation/cases.jsonl) uses only synthetic documents. Each case identifies a question and one expected source for retrieval. Its purpose is a reproducible integration smoke test, not a clinical accuracy score.

Run after ingesting all `sample_data/*.txt` through [`scripts/demo.ps1`](../scripts/demo.ps1). `./scripts/evaluate.ps1` checks whether the expected source ranks first and appears in the top three `/search` hits for each case. For any `/answer` response, check that citations refer to actual retrieved source/version pairs. The automated API tests separately verify `/answer` abstention on an empty collection. An unrelated query against a populated collection is not a reliable no-hit test unless the score threshold has been calibrated. Record the application commit, embedding model, collection, fixture version, hit@1/hit@3 counts, and abstention outcome. Do not compare scores across changed models or document sets without rerunning the same benchmark.

The cases are intentionally small and easy. Passing them shows that the API, embedding, vector store, provenance, and abstention wiring work together. It does not establish semantic relevance across a broad corpus, prompt-injection resistance, calibrated confidence, medical accuracy, or production-scale latency. Extend the set with reviewed real-use cases and adversarial documents before deployment to a sensitive environment.
